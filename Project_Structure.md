Functional map of the codebase. Read this before proposing any change; log every file
addition, move, or removal in the Changelog table immediately (`scripts/verify_structure.py`
enforces it).

| `Project_Structure.md` | **Architecture Map**: this document, including the Changelog. |
| `Function_Mapping.md` | **Errand Map**: each errand script mapped to its site, reads, writes-up-to, secrets, and handoff point. |
| `MEMORY.md` | **Operating ledger**: identity and environment, known site traps, "Errands run" table, session ids, open items. Read at session start. |
| `README.md` | Setup and usage. |

## Application Layer

| Path | Purpose |
| :--- | :--- |
| `headless/` | Reusable package: `config.py` (env and paths), `session.py` (headed persistent Chrome via Playwright or CDP attach), `secrets.py` (Keychain / GCP Secret Manager seam), `profile.py` (registry of typeable values), `gates.py` (preview / apply / check modes and the human handoff), `fields.py` (`FieldPlan`, `Source`, `redact`, `resolve_source`), `preview.py` (redacted screenshot + field-diff artifacts), `errand.py` (`Errand` base class and the run state machine). |
| `scripts/check_env.py` | Environment self-test: Chrome, profile dir, Playwright, secrets backend. |
| `scripts/probe.py` | First errand: open a URL in the Headless profile and write a preview artifact. |
| `tests/` | `pytest` unit tests for pure logic, plus an opt-in browser suite (`test_gates_browser.py`, `HEADLESS_TEST_BROWSER=1`) against `tests/fixtures/form.html`. |
| `previews/` | Redacted preview artifacts written at runtime. Gitignored; absent until first run. |
| `requirements-gcp.txt` | Optional extra: `google-cloud-secret-manager`, imported lazily by `headless/secrets.py` only when the `gcp` backend is selected. Not part of `requirements.txt`. |

A visible Chrome window popping up during test/smoke/errand runs was interfering with the Director's work, so Headless is now invisible unless a window is actually needed. Two independent `Config` axes: `headed` (can a real windowed Chrome be produced - `HEADLESS_HEADED`/`--headless`, unchanged meaning) and `show` (is the window visible from launch - `HEADLESS_SHOW`/`--show`, new, default `False`). Preview and check now launch Chrome's own headless mode by default, ignoring `HEADLESS_HEADED` entirely, unless `--show`. Apply still always opens a real window (the handoff needs one) but hides it immediately after launch and restores/surfaces it only at `handoff()`, right before "Your turn" - never on the CDP-attach path, which must never touch the Director's own browser window. `--headless`/`--show` are now their own mutually exclusive flag group; `--headless` with `--apply` is still refused. Empirically verified on this machine that hiding is best-effort, not a hard guarantee: neither CDP's reported `windowState: "minimized"`, the `--start-minimized` launch arg, nor `--window-position=-32000,-32000` had any real effect; `osascript` native minimize needs a one-time interactive Accessibility grant this session could not make; what worked partially was a post-launch `Browser.setWindowBounds` position push towards the screen's bottom-right corner, which macOS clamps to a small sliver rather than eliminating entirely - see `PATTERNS.md`. `constitution.md` bumped to 1.1.0 (MINOR: materially changed Browser guidance). Commit gate stays green: 112 unit tests (up from 96) under 1 s, opt-in browser suite (still fully headless) 7 tests. |
